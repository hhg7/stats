Yes. Proposed and built this interface (consistent with auc/roc):

  bedroc(\@scores, \@target,
         alpha  => 20.0,     # early-recognition weight (Truchon-Bayly default 20)
         cutoff => 6.5,      # (opt 1) value >= cutoff in @target => active
         positive => 1,      # OR label-based actives when no cutoff is given
         direction => '>',   # '>' higher score ranks first (default); '<' flips
         top    => 0.05);    # (opt 3) also report enrichment in the top 5%

Work performed:

* Validated the formula against an independent R reimplementation of Truchon &
  Bayly (2007) BEDROC, eq. 36:
      BEDROC = RIE * factor1 + factor2
      RIE     = (sum over actives of exp(-alpha*rank_i/N)) / random_expectation
      rank 1 = top of the descending-score ranking; midranks used for ties.
  Caught and fixed an early draft-formula bug (a "perfect ranking" gave 0.011
  instead of ~1 because the sum had been divided by n instead of normalized by
  the random-expectation sum). After the fix:
      perfect ranking  -> 1
      worst ranking    -> 0
      direction '<'    -> flips correctly
      cutoff mode      -> works

* Added the bedroc XSUB to LikeR.xs (right after roc). It reuses the ROCPt
  struct and rocpt_cmp_desc comparator from roc, sorts descending, assigns
  average (mid)ranks to ties, sums exp(-alpha*midrank/N) over actives, and
  computes BEDROC, RIE, rie_min, rie_max. cutoff-mode selects actives as
  @target values >= cutoff; top-mode adds an enrichment sub-hash
  (fraction, n_top = ceil(top*N), active_count, expected = ra*n_top,
  enrichment_factor = (active_count/n_top)/ra).

  Result hash keys: bedroc, alpha, rie, rie_min, rie_max, n, n_active,
  n_inactive, ra, direction, method, and (with top =>) enrichment.

* Added bedroc to @EXPORT_OK in lib/Stats/LikeR.pm.

* Wrote t/bedroc.t (47 tests): reference values, alpha sensitivity, perfect/
  worst bounds, direction '<', string labels via positive=>, cutoff mode,
  top-fraction enrichment, help capture, error paths, and no_leaks_ok.

* Full suite: 5022 tests PASS. Zero new -Wall/-Wextra warnings in the new code.

* Documented bedroc in README.md only (alphabetically between auc and bfill).
  read.me.pod left untouched (it is generated from README.md via md2pod.pl).

my $bedroc = bedroc(
    vals($m, 'r. rank'),
    vals($m, 'ΔG rank'),
    alpha => 32.2,
    direction => '<',
    top => 0.1
); what am I doing wrong?


--------------------------------------------------------------------------------
ASSISTANT:
--------------------------------------------------------------------------------
vals() returns an arrayref, so passing the two calls positionally is fine — that
is NOT the bug. The bug is what the SECOND array means.

bedroc's second argument must be a BINARY active/inactive indicator, not a second
ranking. Passing 'ΔG rank' (values 1,2,3,...N) with no cutoff means the default
positive => 1 marks as "active" only the single row whose ΔG rank equals "1" and
treats everything else as inactive. So it silently computes BEDROC for a
one-active problem — a meaningless number, not an error.

BEDROC answers: "does my score ranking pull the known actives to the top early?"
So you must define which compounds are the actives — presumably the best binders,
i.e. the top fraction by ΔG. Because ΔG rank == 1 is the BEST binder, actives are
the SMALL ranks:

    my $r_rank  = vals($m, 'r. rank');
    my $dg_rank = vals($m, 'ΔG rank');

    my $k = 0.10 * @$dg_rank;                     # actives = top 10% by ΔG
    my @active = map { $_ <= $k ? 1 : 0 } @$dg_rank;

    my $bedroc = bedroc(
        $r_rank, \@active,
        alpha     => 32.2,
        direction => '<',      # r. rank: 1 = best, so lower ranks first (this was right)
        top       => 0.1,
    );

Demonstration (30 compounds, r-rank tracking ΔG-rank closely):
    as-written: n_active=1  bedroc=0.3419  (only the single ΔGrank==1 row is active)
    corrected : n_active=3  bedroc=0.9473  EF(top10%)=6.67  (n_top=3, hits=2)

Two cautions:
  * Don't use cutoff => here naively: cutoff selects value >= cutoff, but ΔG rank
    is "good = small", so cutoff => 3 would pick the WORST compounds. Building the
    0/1 label with <= (as above) is the clear way. (If you insisted on cutoff,
    you'd negate: [map {-$_} @$dg_rank] with cutoff => -3.)
  * If you actually wanted rank-vs-rank AGREEMENT (not early recognition of a
    defined active set), BEDROC is the wrong tool — use Spearman/Kendall
    (cor(... method => 'spearman')).
